# ADR-014: 모바일은 CSS 분기가 아니라 서버 판정 + 전용 위젯 트리로 나눈다

- **상태**: ✅ 채택·구현 완료 (prod 반영, PR #408)
- **일자**: 2026-05-28 (설계) / 2026-06-15 (prod)
- **관련**: [#340](https://github.com/pfplay/pfplay-web/issues/340)(스코프 확정, closed), 모바일 chunk 1~6 PR 시리즈
- **관련 코드**: `src/middleware.ts`, `src/widgets-mobile/`, `src/features-mobile/`, `src/app/**/page.tsx`

## 배경

이전에는 모바일 UA 를 미들웨어에서 잡아 **`/mobile-notice` 로 전면 차단**했다. 공유 링크로 들어온
모바일 유입이 구조적으로 발생하는데(파티룸 링크·`share-link`), 그 유입이 전부 벽을 만나고 있었다.

모바일을 열기로 하면서 두 갈래가 있었다.

- **(A) 하나의 컴포넌트 트리 + CSS 반응형** — 브레이크포인트로 레이아웃만 바꾼다.
- **(B) 모바일 전용 위젯 트리** — 화면 구성 자체를 다르게 만든다.

파티룸의 데스크탑 UI 는 절대좌표 멀티패널(아바타 캔버스, 전광판, 사이드 패널)이다. 이걸 CSS 로
stacked 모바일 레이아웃까지 커버하려면 한 컴포넌트가 두 개의 상이한 정보 구조를 동시에 만족해야
하고, 어느 쪽을 고쳐도 반대쪽이 깨진다. 게다가 **모바일에서는 기능 자체를 덜어내기로** 확정했다
(아바타 캔버스·모더레이션·룸 생성·아바타 편집 제외, 최소 큐잉만).

즉 차이가 "레이아웃" 이 아니라 **"무엇을 보여주는가"** 였다.

## 결정

**(B) 를 채택한다.** 다만 클라이언트에서 뷰포트를 재는 대신, **서버에서 디바이스를 판정해
페이지 단위로 트리를 고른다.**

1. `src/middleware.ts` 가 UA 를 보고 요청 헤더에 **`x-pf-device: mobile | desktop`** 을 주입한다.
   (리다이렉트하지 않는다 — 차단 로직은 제거됐다.)
2. 각 `page.tsx` 가 `headers().get('x-pf-device')` 로 분기해 데스크탑/모바일 트리를 렌더한다.
   현재 분기 지점: 파티룸 로비·파티룸 상세·설정(프로필/아바타/알림).
3. 모바일 전용 구현은 `src/widgets-mobile/`, `src/features-mobile/` 에 둔다.
   공통 로직(entities, shared, API, 스토어)은 **그대로 공유**한다.

## 왜 클라이언트 측정이 아니라 서버 헤더인가

- **깜빡임이 없다.** 클라이언트에서 뷰포트를 재면 첫 페인트가 데스크탑으로 나갔다가 교체된다.
- **SSR 이 정직해진다.** 서버가 처음부터 맞는 트리를 렌더하므로 하이드레이션 불일치가 없다.
- 판정 근거가 한 곳(`middleware.ts`)에 모인다.

## 결과

**얻은 것**

- 모바일 화면이 데스크탑을 인질로 잡지 않는다. 모바일 위젯을 고쳐도 데스크탑 회귀 위험이 없다.
- 모바일 전용 e2e project 로 독립 검증이 가능하다(`e2e/mobile/`).
- `/mobile-notice` 차단이 사라져 공유 링크 유입이 실제 전환 경로가 됐다.

**받아들인 비용**

- **UI 가 두 벌이다.** 같은 기능을 양쪽에 구현해야 하고, 한쪽만 고치는 실수가 가능하다.
  → 모바일 위젯을 만들 때는 **데스크탑 구현을 먼저 grep 해서 기준선을 확인**하고, 차이가
  의도된 것인지 명시한다.
- UA 판정은 태블릿·데스크탑 축소창 같은 경계에서 완벽하지 않다. 서비스 목표(공유 링크 모바일
  유입)에 비해 허용 가능한 오차로 판단했다.
- 데드코드가 남아 있다: `src/app/mobile-notice/*`, `src/widgets/mobile-fallback-card`.
  더 이상 도달 불가하며 별도 정리 대상이다.

## 관련 제약

- 모바일 전광판(YouTube 임베드)은 **ToS 최소 크기(≥200×200)** 를 지켜야 한다. 과거의 80×45
  축소 토글은 정책 위반이라 제거됐고, `e2e/mobile/display-board.tos.spec.ts` 가 회귀를 잠근다.
- 모바일에서 게스트 채팅은 의도적으로 막는다(데스크탑은 허용). 전환 압력을 위한 분기다.
