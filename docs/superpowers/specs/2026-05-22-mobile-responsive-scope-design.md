# 모바일 반응형 개편 — 최소 필수 기능 스코프

> **작성일**: 2026-05-22
> **상태**: 스코프 확정 (레이아웃·구현 설계는 후속 단계)
> **선행 문서**: [`2026-04-19-mobile-desktop-redirect-design.md`](./2026-04-19-mobile-desktop-redirect-design.md) — 이 스코프가 그 문서의 "향후 제거" 트리거다.

---

## 목적 / 배경

현재 모바일은 `src/middleware.ts`의 `isMobileUA` 판정으로 **모든 페이지가 `/mobile-notice`로 전면 차단**된다. 반응형 개편을 진행하되, **데스크탑 전 기능을 모바일로 옮기지 않는다.** "사용자가 이 서비스의 핵심을 느낄 수 있을 정도"의 최소 필수 조합만 모바일로 가져온다.

**1차 목적 = 공유링크 유입 전환.** `link/[linkDomain]` 라우트와 `share-link` 기능이 이미 있어 모바일 유입은 구조적으로 발생한다. 누군가 파티룸 링크를 폰으로 열었을 때 핵심을 체감하고 → 가입하거나 → 데스크탑으로 넘어오게 만드는 깔때기가 모바일 버전의 존재 이유다. 방문자는 대개 **게스트 상태**로 룸에 도착한다.

## 설계 렌즈: "맛보기(taste) → 전환(convert)" 깔때기

게스트로 도착해 핵심 감각을 _로그인 없이_ 체험하고, 더 깊은 행동(DJ·채팅)에서 로그인 게이트를 만나는 것 — 이 게이트 자체가 가장 자연스러운 전환 장치다. 따라서 기능 선택과 **게이팅(누가 무엇을 할 수 있는가)**을 함께 설계한다.

## 확정 결정 (잠금)

| #   | 결정              | 값                                                                              |
| --- | ----------------- | ------------------------------------------------------------------------------- |
| 1   | 모바일 1차 목적   | 공유링크 유입 전환                                                              |
| 2   | 참여 깊이         | **DJ 포함 (풀 참여)** — "내가 음악을 튼다"가 최강 매직이자 전환 미끼            |
| 3   | 플레이리스트 범위 | **최소 큐잉만** (DJ는 어차피 로그인 게이트 뒤). 라이브러리 관리는 데스크탑      |
| 4   | 공존감 표현       | **전체 아바타 캔버스 OUT.** 현재 DJ 식별 + 크루 목록(아바타 썸네일)로 대체      |
| 5   | 게스트 채팅       | **모바일에서 차단** (데스크탑은 게스트 채팅 허용 — 의도적 분기, 전환 압력 강화) |

## IN — 모바일 최소 필수 (게이팅별)

### 🟢 게스트 맛보기 (로그인 불필요)

| 묶음            | 기능                                       | 코드 (현행)                                                      |
| --------------- | ------------------------------------------ | ---------------------------------------------------------------- |
| 랜딩·입장       | 공유링크 랜딩 → 룸 직행, 입장/퇴장         | `app/link/[linkDomain]`, `features/partyroom/enter`·`exit`       |
| 동기화 재생 🎵  | 전광판 · now-playing                       | `widgets/partyroom-display-board`, `entities/current-partyroom`  |
| 현재 DJ 식별 🎧 | 지금 트는 사람 아바타+닉을 전광판에 작게   | display-board 내 DJ 표시 (bounded, 공간 부담 없음)               |
| 크루 현황 🫂    | "N명 청취 중" + 목록 (각 줄 아바타 썸네일) | `features/partyroom/list-crews`, `widgets/partyroom-crews-panel` |
| 리액션 ❤️       | 현재 곡에 반응                             | `features/partyroom/evaluate-current-playback`                   |
| 로비 브라우징   | 파티 목록 탐색 ("다른 방 뭐 있지?")        | `app/parties/(lobby)`, `features/partyroom/list`                 |
| 공유            | 룸 재공유 (깔때기 순환)                    | `features/partyroom/share-link`                                  |

> 게스트가 _로그인 없이_ "혼자가 아니고, 같은 곡을 같이 듣고, 반응할 수 있다"는 핵심 감각을 체감하는 구간.

### 🔒 로그인 게이트 (전환점)

| 묶음           | 기능                                           | 코드 (현행)                                                                                                    |
| -------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 소셜 로그인 🔑 | 전환 행동 자체 (DJ/채팅 시도 시 트리거)        | `features/sign-in/by-social`                                                                                   |
| 채팅 💬        | 메시지 전송/조회 (**모바일은 게스트 차단**)    | `features/partyroom/send-chat-message`·`list-chat-messages`, `_panels/chat-tab-panel`                          |
| DJ 🎧          | 큐 등록/해제 · 큐 보기                         | `widgets/partyroom-djing-dialog`, `features/partyroom/list-djing-queue`                                        |
| 최소 큐잉      | 곡 검색·추가 + DJ용 플레이리스트 선택 + 프리뷰 | `features/playlist/add-tracks`, `features/partyroom/select-playlist-for-djing`, `widgets/music-preview-player` |
| 지금 곡 저장   | 재생 중인 곡을 내 플레이리스트에 grab          | `features/partyroom/grab-current-playback`                                                                     |

> "더 깊이 참여하려면 가입" — DJ가 최강 미끼. 모바일은 채팅까지 게이트로 묶어 전환 압력을 더 건다.

## OUT — 데스크탑 전용으로 남김

| 영역                                                                                                                       | 제외 사유                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **전체 아바타 캔버스** (`widgets/partyroom-avatars`, `PartyroomAvatars`)                                                   | 떠다니는 청취자 아바타 공간 연출 — 모바일 화면에 공간 없음. DJ 식별 + 크루 썸네일로 대체      |
| **아바타 커스터마이징** (`settings/avatar`, `features/edit-profile-avatar`)                                                | 과금/프리미엄 영역 + 데스크탑 전환 미끼. _표시는 IN, 편집은 OUT._ 게스트는 기본 아바타로 충분 |
| **플레이리스트 라이브러리 관리** (`features/playlist/`의 add·edit·change-track-order·move-track-\*·remove·list-tracks)     | 멀티 생성·정렬·이동·편집. 모바일은 최소 큐잉(add-tracks)만                                    |
| **모더레이션 전체** (`block-crew`, `impose/lift-penalty`, `adjust-grade`, `lock/unlock-djing-queue`, 오너 `skip-playback`) | 룸 오너 파워유저 도구                                                                         |
| **룸 생성** (`features/partyroom/create`)                                                                                  | 방문자는 남의 방에 입장. 내 방 만들기는 호스트 행위 = 깊은 커밋                               |
| **프로필/바이오 편집** (`features/edit-profile-bio`)                                                                       | 정체성 편집은 데스크탑                                                                        |
| **버그리포트** (`features/bug-report`), **회원탈퇴** (`features/withdraw`)                                                 | 핵심 체감과 무관                                                                              |
| **cinema 모드** (`useUIState.cinemaView` 분기)                                                                             | 데스크탑 와이드 전용 연출                                                                     |

## ⚙️ 자동 승계 (피처 선택 아님 — 횡단 인프라)

모바일에서도 그대로 동작해야 하며 스코프 선택 대상이 아니다.

- **점검/공지 오버레이** — middleware page rewrite + WS overlay (`features/system-announcement`, maintenance)
- **i18n** — ko/en (`features/change-language`는 진입점만, 자동 쿠키 기반)
- **presence · WS** — 단일 파티룸 구독 invariant 유지 (클라+백엔드 양쪽 방어)

---

## 구조적 함의 (후속 레이아웃 설계 예고 — 본 스코프 결정 아님)

현재 룸은 데스크탑 **절대좌표 멀티패널**이다: 중앙 전광판 + 좌 사이드바(프로필/플레이리스트/DJ/공유) + 우 채팅·크루 패널 + cinema 모드 (`app/parties/(room)/[id]/page.tsx`). 위 IN 묶음을 모바일 한 화면에 담으려면 **stacked 구조**로 재배치가 필요하다 — 피처는 그대로, 레이아웃만 접는 방향. (예: 전광판 상단 고정 + 하단 탭[채팅/크루/DJ] + 리액션 플로팅 — _방향성일 뿐 확정 아님_.)

또한 본 개편 착수는 선행 문서의 "향후 제거" 1~4번(`isMobileUA` 미들웨어 분기, `MobileGuard`, `/mobile-notice`, i18n 키)을 트리거한다.

## 비목표 (Non-goals)

- 모바일 레이아웃 상세 설계 / 컴포넌트 분해 / 구현 순서 — **별도 단계**
- 모더레이션·아바타 편집·룸 생성의 모바일화
- 데스크탑 동작 변경 (게스트 채팅 등은 데스크탑에서 그대로)

## 미해결 / 후속 확인

1. **리액션 게스트 허용** — `evaluate-current-playback`가 `ROLE_GUEST`에서 동작하는지 백엔드 확인 (게스트 맛보기의 핵심 1건)
2. **모바일 게스트 채팅 차단 위치** — 데스크탑이 게스트 채팅을 허용하므로 백엔드 변경 없이 **모바일 클라측 게이트**로 충분할 가능성 높음. 검증 필요
3. **곡 검색 소스** — `add-tracks`의 검색/프리뷰 소스와 모바일 UX (좁은 화면에서 검색→프리뷰→큐)
4. **공존감 카피 톤** — DJ 식별/크루 카운트가 "온기"를 충분히 전달하는지 실측 (headed 측정)
